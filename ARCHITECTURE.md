# CareNexus — Architecture Overview

_Last updated: 2026-06-09 (final certification audit)_

## 1. High-Level Architecture

CareNexus is a monolithic, multi-tenant B2B SaaS platform designed for NHS mental health trusts.

It is structured as a pnpm monorepo:
- `@workspace/api-server` — Node.js / Express 5 REST API
- `@workspace/web` — React 18 / Vite / Tailwind SPA
- `@workspace/api-spec` — OpenAPI definition and Orval Codegen

## 2. Security & Multi-Tenancy Architecture

### Hard Tenant Isolation
Every operational database row (Patients, Appointments, Tasks, Outcomes) includes a `tenantId`. 
All incoming requests pass through `requireTenant` middleware, which extracts the `tenantId` from the JWT token and mounts it on `req.tenantId`. All Prisma queries are forcefully scoped using this ID. `assertTenantMatch` prevents ID-hopping on mutations.

### Authentication
- JWT access tokens (8h) and refresh tokens (30d) stored in **HttpOnly cookies**.
- CSRF protection is planned (currently missing).
- Rate limiting implemented on authentication endpoints.

### RBAC (Role-Based Access Control)
- Static role group checking (`ADMIN_ROLES`, `CLINICAL_ROLES`, `ALL_ROLES`) operates correctly.
- Granular permission enforcement against the `role_permissions` table is architected but currently bypasses runtime enforcement (Security Bug).

## 3. Backend Stack (api-server)

- **Framework:** Express 5 (native Promise support, no `try/catch` wrapping needed for async handlers).
- **ORM:** Prisma, generating TypeScript definitions against a PostgreSQL database.
- **Validation:** Zod schemas.
- **Logging:** Pino (request-scoped JSON logs).
- **Scheduled Jobs:** `node-cron` (runs nightly risk scoring recalculation at 02:00 AM).

### Core Services Layer
- `RiskScoringService.ts`: Weighs missed appointments, overdue tasks, missing consults, and program non-compliance to generate 0-100 risk scores.
- `notificationService.ts`: Central non-blocking helper for triggering in-app alerts.
- `audit.ts`: Captures JSON snapshots of entities before/after mutation.
- `SyncWorker.ts`: Legacy polling synchronization worker.

## 4. Frontend Stack (web)

- **Framework:** React 18 + Vite.
- **Data Fetching:** React Query (Hooks automatically generated by Orval from OpenAPI spec).
- **Routing:** React Router DOM (with `AuthGuard` layout wrapping).
- **State Management:** Zustand (minimally used; React Query handles server state).
- **Styling:** Tailwind CSS + shadcn/ui components (Radix primitives).
- **Charts:** Recharts.

## 5. Development Workflow (API Contract First)

1. Modify `schema.prisma` and run `pnpm run db:push`.
2. Modify backend route logic in `api-server`.
3. **CRITICAL:** Update `openapi.yaml` in `api-spec`.
4. Run `pnpm run codegen` in `api-spec` to build React Query hooks.
5. Consume strongly-typed hooks in `web`.

*Note: As of this audit, Phase 1-5 backend endpoints are implemented but Steps 3-5 have not been executed. This is the primary development blocker.*
